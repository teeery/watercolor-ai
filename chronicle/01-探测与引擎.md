# 01 · 探测与引擎

## 开源引擎探测（结论：借用算法，不借用程序）

- 起因：先想清楚要不要自研，调研了 8 个开源方案 + Tyler Hobbs 指南 + sudoaquarelle。
- 实测 Open-Watercolor-Sim（唯一可被 agent 驱动的候选）：Apache-2.0、可 pip 装、无头可驱动（paint→step→render）、CUDA 可跑（它用 taichi 已删的 `ti.core` 探测 GPU，4 行 shim 绕过）。还发现它的 `set_color` 会被 update_params 用默认紫红覆盖（官方 demo 可能也中招）。
- 结果：vision 给官方 demo 打 **2.5/10**（"带颜色的雾"），我们调参到极限也只有 3/10，回流机制结构性缺失。**判定：机制可驱动但质量不过门槛，修补 = 重写其内核，借用无成本优势。**
- 决策（你拍板）：B+C 方案——自研 JS 引擎，OWS 留作对照基准。教训沉淀在 `probe/OWS-评估.md`。

## JS 引擎从零到跑通

- 纯 JS + Float32Array，零依赖，640×480 网格，九步管线（流场→水平流→掩码扩张→颜料平流→沉积→前缘沉积→边缘加深→蒸发→冻结）。
- 参考：Hobbs 指南 + Curtis SIGGRAPH'97 专利（`docs/watercolor_engine_spec.md`，专利全文在 `research/`）。

## 早期 bug 三连（详见 05-参考速查 的 bug 清单）

1. 滑动窗口 blur 初始化累加整行 → 水场变负、颜料消失。
2. 补色装反：颜料 RGB 直接当吸收量，天空蓝渲染成赭褐。
3. 画布边缘被 bbox 排除在蒸发外 → 边缘成"永恒水库"，水永不干。

## 首版验收

- vision：2/10 → 修完 3/10。诊断：等距盖章成竖条纹、干皴像印章、色滩过圆、清水滴无回流。
- 教训：第一版的问题一半在引擎、一半在我的笔触生成太机械。
