# 08 · 可画性十基元电池 v0.1（随机贪心求解下界——一个重要负面结果）

> 阶段范围：Oracle 1 结论落地后，把「几何可达域」从单张《乡村田野》泛化到 `docs/paintability.md` 定义的十个正交基元。
> 一句话：**v0.1 没量出可达域，反而量出了一个更值钱的东西——我们拿「随机贪心」当 oracle，而它弱到连一条直线都搜不到。**

## 1. 做了什么

- `demo/paintability/battery.js`：8 个平涂可测基元（直线 / 曲线尖叶收锋 / 三角T闭合 / 边缘谱 / 平滑渐变 / 透明罩染 / 空间频率条纹 / 负形留白提色）各一张程序化目标图（用同一套 `FlatCanvas` 原语画出的"理想平涂"）→ `fitFlat` 贪心拟合 + 颜色精修 → MSE + 形状区 PSNR + 三栏蒙太奇（目标|拟合|误差）。
- 复用了 Oracle 1 的工具链（`src/paintability/{flat,oracle1}.js`）；9(湿画湿)、10(干燥细节) 标注 defer（需介质引擎）。

## 2. 结果（原始数字）

| 基元 | 形状区 PSNR |
|---|---|
| 1 直线 | 7.33 |
| 2 曲线尖叶 | 10.67 |
| 3 三角T闭合 | 10.63 |
| 4 边缘谱 | 12.78 |
| 5 平滑渐变 | 19.51 |
| 6 透明罩染 | 20.34 |
| 7 频率条纹 | 6.68 |
| 8 负形留白 | 12.59 |

乍看是"8/8 不可达、引擎全废"。

## 3. 为什么这个结论是错的（vision 自检抓住的）

- 我按纪律用 vision 复核蒙太奇，结果：**1_line 中栏连五条直线都没画对**——竖线只剩灰影、斜线基本漏掉、粗细没重现、误差沿线的位置全红。
- 但直线就是「一笔 ribbon」，而目标本身就是 `FlatCanvas.ribbon` 画出来的。**表示能画一条直线，这是平凡真**——于是"搜不到直线"只能说明**求解器（随机贪心）太弱**，不是表示/引擎不可达。
- 6(透明罩染)、7(频率条纹) 复核同病：拟合用一堆乱叠椭圆/矩形去糊，细条纹被平均成灰，连"清晰重现状"都做不到。
- 对照 `docs/paintability.md` 分锅规则：**random-greedy 逼近不了 → 先修 oracle，不能给引擎甩锅。**

## 4. 教训（这轮真正值钱的地方）

1. **「随机提案 + 残差采样」的贪心不是 oracle**，而是求解下界——它对 `docs/paintability.md` 里"参数扫描 + 随机/进化"只实现了一半（随机，缺参数扫描），而且随机提案命中细直线的概率趋近于零。
2. **平涂目标与原语同源 → 可达性平凡真**，平涂电池只能测求解器，测不了引擎。要测引擎可达域，渲染器必须是**介质引擎**（干画输出），目标仍是平涂 SVG。
3. 下一版 oracle 至少二选一：**(a) 直接参数扫描/坐标下降**（逐基元按其参数形式直接拟合，如直线搜角度/位宽）；**(b) 进化搜索**覆盖几何+alpha+颜色。二选一之前，"可达/不可达"的裁决一律不作数。
4. 自治循环的复核价值被再次验证：数字会说谎（"8/8 不可达"），vision 一眼就看出"它连直线都没画出来"——所以每轮数字结论后面必须跟一张人能看的图。

## 5. 状态与解耦

- v0.1 交付物按「求解下界」口径保留：`demo/paintability/battery.js` + `out/paintability/summary.json`（gitignored 产物）+ 8 张蒙太奇；summary 里 `metric` 字段已标注"随机贪心求解下界（非可达域）"。
- 后续：真 oracle（参数扫描/进化）→ 再决定是否上介质引擎渲染器。二者是独立的下一步，互不阻塞。
- 关联：Oracle 1 的「卡通/低通天花板」结论不受影响——那是贪心的**上界**测量（再强的求解也难破 ~17-19dB），这轮的贪心在此处是被当作**下界**用，性质不同、不可混用。

## 6. 直基元真 oracle 实测（把「求解器锅」钉死为可复现数字）

`demo/paintability/oracle-line.js` —— 同一条直线（一笔 ribbon），三种求解器：

| 求解器 | 形状区 PSNR |
|---|---|
| 随机贪心（fitFlat） | 6.59 dB |
| 局部坐标下降（无初值） | 4.80 dB |
| **全局粗网格 + 局部精修（「参数扫描」）** | **172.52 dB**（≈浮点精确重建） |

- 结论：**表示一条直线是平凡可达的（oracle 直接重建到 ~∞）；v0.1 的低分全在求解器**——细直线的损失地形是「针尖单点」，局部/贪心搜索几乎处处无梯度、卡死。`docs/paintability.md` 说 oracle 是「参数扫描 + 随机/进化」：**随机没有扫描做前导，就是这轮的下场。**
- 对 agent 主线的隐喻：真画家是「先看、再落笔」（vision 提供全局定位 = 一种"扫描"），而不是盲掷残差采样；这句把「oracle 形态」与「agent 循环为何需要 vision 阶段批评」接上了。

## 7. v0.1 表示层裁决（修正口径，取代第 2 节的"8/8 不可达"误读）

| 基元 | 表示层可达性 | 贪心下界 |
|---|---|---|
| 1 直线 / 2 曲线尖叶 / 3 三角T闭合 / 4 边缘谱 / 6 透明罩染 | **可达**（目标由同词汇构造，且 line 已被 oracle 实测背书） | 7–20 dB |
| 5 平滑渐变 | **部分可达**（真平滑需 ∞ 步 → 条带地板，非平面原语可达） | 19.5 dB |
| 7 空间频率条纹 | **可达但=奈奎斯特壁**（1px 条纹已到 480×640 网格极限） | 6.7 dB |
| 8 负形留白提色 | **平涂代理可达**；真"提色揭示纸纹"需介质引擎 | 12.6 dB |
| 9 湿画湿 / 10 干燥细节 | — 介质引擎，defer | — |

→ 十基元电池的**真·可变性边界**只剩：5(平滑度)、7(频率壁)、8(真减法)、9/10(介质)——这些才是下一步真 oracle + 介质引擎要打的靶，几何三件套(1/2/3)与硬软边(4)、罩染(6)已知可达。
