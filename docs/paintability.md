# 可画性基准（Paintability Bench）

> 前置于一切 AI 优化的问题：**这台引擎"可画"吗？**
> 控制论里叫可控性，绘画里叫可画性：给定笔刷动作空间、纸张与介质动力学，系统能稳定实现哪些形状、边缘、空间频率、颜色、透明层次？这个集合就是**介质可达域**。
> 此前文档从未建立这个研究对象——paradigm 与 architecture 默认"引擎能画、品味在 agent"，这是未验证的假设。

> 关联：`docs/oracle1.md` 是同一问题（可画性）的第一块多米诺——**平面笔触拟合**《乡村田野》已落地，结论是平涂也在低位平台（≈17.5 dB），指向「先补笔触表示」；十基元电池是把这一结论从单张画泛化到逐基元的正交测量。

## 为什么这是漏掉的核心问题

- 即使 AI 完美，若动作集合与介质动力学根本产生不了目标图像，它也不可能成功——**锅不在 agent，在引擎/动作基底**。
- 此前对全景 6.5/10 的归因是"物体笔触品味留待 agent 层解决"。这个归因本身未经验证：必须先证明 oracle（最优求解器）画得出，才有资格让 agent 背锅。
- **分锅规则**：oracle 寻优能逼近 → agent 的问题；oracle 逼近不了 → 引擎 backlog 的债。

## 已知嫌疑清单（按控制论归因）

| # | 嫌疑 | 归因 | 现有关联 |
|---|---|---|---|
| 1 | 动作基底过窄：笔刷只能圆斑/断裂印章，连续草叶不可达 | brush 形状库缺 | engine.md P1「笔刷形状库」 |
| 2 | 扩散下界：小尺度结构被平滑，细线（如瓦线）不可保存 | core 扩散算子 + 网格分辨率 | 无条目（新增） |
| 3 | 动作不可逆：所有动作只增颜料，提色能力有限，早期错误不可恢复 | core lift 能力未量化 | stroke 类型含 `lift`，但能力未测 |
| 4 | 频率上限：640×480 模拟网格（1280×960 画布 ×0.5）决定可控空间频率上限 | core 网格 | roadmap 开放问题「性能预算」 |
| 5 | 动作—响应失配：干笔长轴方向错误，期望动作 ≠ 实际响应 | brush→core 耦合（dry-brush 实现） | engine.md backlog 原则「因果耦合优先」 |

纪律：每个嫌疑必须被基准**证实或证伪**后，才允许进 engine.md backlog。

## 基准电池：十个正交基元

不能先拿复杂风景测——风景失败无法归因。先测正交基元，每个基元只测一个维度：

| # | 基元 | 测什么 | 典型失效指向 |
|---|---|---|---|
| 1 | 不同方向与宽度的直线 | 基本笔画保真、方向不变性 | 嫌疑 1/5 |
| 2 | 曲线、尖叶、收锋 | 连续曲率 + 尖端点（收锋） | 嫌疑 1 |
| 3 | 三角形、T 型连接、封闭轮廓 | 几何拓扑：角点、接头、闭合 | 嫌疑 1/2 |
| 4 | 硬边、软边、一边硬一边软 | 边缘谱（单一控制轴上的可调性） | 嫌疑 2 |
| 5 | 平滑渐变与分段渐变 | 强度连续域的可控性 | 嫌疑 2/4 |
| 6 | 单层与多层透明罩染 | 透明层次（glaze 叠层） | 颜色/层次可达域 |
| 7 | 不同空间频率的条纹 | 频率响应 → 可达频率上限（与网格对比） | 嫌疑 4 |
| 8 | 负形、留白、局部提色 | 减法能力：擦/留/提 | 嫌疑 3 |
| 9 | 湿画湿受控边界 | 趁湿状态下的边界可控性 | 嫌疑 2 |
| 10 | 完全干燥后的细节保真 | 干燥时间线对结构的破坏量 | 嫌疑 2/4 |

每个基元：目标图（程序生成，无歧义）→ oracle 寻优 → 最终干画 → **目标—干画的最低可能误差**。

## 方法

1. **目标**：每基元一张目标图。几何目标用参数化形状/平涂 SVG，不用自然照片——保证无歧义。
2. **oracle**：自动搜索最优笔触序列（初始：参数扫描 + 随机/进化搜索；将来升级为 RL 路线，见"神经升级缝"讨论）。oracle 不是要当画家，是要测下限。
3. **度量**：目标—最终干画误差（ΔE 色差图 + 结构相似度；主观复核用 vision 评审）。"通过"阈值人定 + vision 复核，每基元不同。
4. **成绩卡**：每基元一张——目标 | 最优干画 | 误差图 | 最低误差数 | 最优笔序 | 失败模式。
5. **结论规则**：
   - oracle 达标 → 记入"可达"清单，agent 层获得优化资格；
   - oracle 不达标 → 转 engine.md backlog，**修引擎先于调 agent**；
   - 长期不可达 → 记为可达域边界，产品层面承认：教学 MVP 选材避开、demo 不承诺。

## 与现有体系挂钩

- **第五检验锚**：architecture.md「检验基准」加入可画性之锚（与前四锚并列，落点 `demo/paintability/`）。
- **backlog 新来源**：基准失败项 → engine.md backlog，优先级由基元重要性裁定。
- **Phase 1 顺序**：教学 MVP 不动引擎、可先行；**agent 循环上线前必须出第一版基元成绩**——先证可画，再谈 AI。
- **与神经升级缝的咬合**：oracle 就是 RL 路线（笔触空间搜索）的退化版；基准失败项是学习式介质参数的靶子；"最优求解器都画不出尖叶"是"换引擎参数还是换动作基底"的裁决依据。
- **与 effects 面板的关系**：`demo/effects.js`（8 格）是能力烟测——"有这个效果吗"；可画性基准是能力量化——"这个效果能到多精确"。
