# 前辈调研：agent 画家论文（册）

> 已录：册一 Intelli-Paint（arXiv 2112.08930 / ECCV 2022）· 册二 Inverse Painting（SIGGRAPH Asia 2024）。

> 结论先行：**这篇是对我们 Phase 1 的"官方背书"，不是威胁，也不进主线的实现方案。** 它用实验证明了"笔序像人"的三个机制——对象级分层（先背景后前景）、随进度收缩的局部注意力窗口、先冗余后裁剪的两阶段结构——恰好覆盖我们 agent-loop 已写但未证的部分；它的介质是 alpha 合成的贝塞尔笔刷，没有水，介质腿和时间线腿仍是我们独占。借鉴方式是**把它的三个机制翻译成 Phase 1 的 prompt / rubric 条款**，不抄 RL。

（册说明：本册与 `predecessors.md`（介质引擎/流体）并列，专门收纳"教机器像人一样作画"的 agent 论文。册一 Intelli-Paint，册二 Inverse Painting；Xie 2013 水墨 Artist Agent、Paint Transformer、SPIRAL、CLIPDraw 等可后续补入。）

## 册一 · Intelli-Paint（arXiv 2112.08930 / ECCV 2022）

## 一、论文速览（已从 PDF 全文核实）

| 项 | 内容 |
|---|---|
| 题 | Intelli-Paint: Towards Developing Human-like Painting Agents（ECCV 2022 正式版：...More Human-Intelligible...） |
| 作者 | Jaskirat Singh、Cameron Smith、Jose Echevarria、Liang Zheng（Adobe Research + 澳大利亚国立大学） |
| 档案 | `research/papers/agent/[2112.08930] Intelli-Paint：迈向开发类人绘画剂.pdf`（ar5iv 中文机翻打印版，31 页含补充材料）；提取全文 `research/probes/ip_text.txt` |
| 链接 | [ar5iv](https://ar5iv.labs.arxiv.org/html/2112.08930) · [ECCV 正式版](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136760662.pdf) · [项目页](https://1jsingh.github.io/intelli-paint) |
| 任务 | 输入一张目标照片，输出一笔一划的 stroke 序列（约 300 笔预算），画布逐步逼近照片 |

### 问题设定

既往方法（RL [Huang 2019]、Optim [Zou 2021]、Paint Transformer [Liu 2021]、Semantic-RL [Singh 2021]）都用**网格渐进分割**：整图 → 逐步细分网格 → 并行画每格。后果：机械、自底向上、中间画布人类看不懂（例如为逼近鸟头直接画红笔触，见论文图 4）。

### 方法：两阶段混合优化

**1. 顺序规划器（RL，基于模型的 DDPG，训练 500 万步 / batch 128）**

- 状态 =（画布、目标图、时间步、全局/局部注意力窗口、显著性图、当前层）；动作 = 13 维二次贝塞尔笔触（位置×6、透明度×4、RGB×3）。
- 三大机制（即论文三项贡献）：
  - **渐进分层**：第 0 层只画背景（显著区域当作背景内容画——鸟站在树上就先画枝叶）；之后按显著度递减逐对象叠加。分层奖励 = WGAN 判别器分数在分层掩膜上的差分。主文 L=2，用 ranked saliency 可扩展到 L>2。
  - **顺序笔触引导**：粗窗口 𝒢_t = 各目标框的凸组合（agent 预测凸系数，ℬ₀ 为全画布）；局部窗口 𝒲_t 用马尔可夫更新，尺寸随归一化时间从整个目标线性收缩到 ≥0.2；ParamAdjust 把笔触参数压进窗口内。
  - **人类一致性惩罚**：空间惩罚 −‖𝒢_{t+1}−𝒢_t‖_F（连续窗口不跳区）+ 颜色惩罚 −‖RGB_{t+1}−RGB_t‖_F（相邻笔触色彩连续）。总奖励还含 guided-backprop 焦点奖励（其前作 Semantic-RL），μ=10，η/γ 按 1e-4→0.1 退火。
- 依赖：U-2-Net 算显著性、YOLO-v5 算目标框。

**2. 笔触正则化（推理时梯度下降）**：每笔挂重要性 β=Sign(x)（x~N(0,1e-3)），优化 ℒ2(画布,目标)+γ·Σ‖β‖₁，削冗余/重叠笔触 **60-80%**（与 Paint Transformer 比总笔数约 1/20）。

### 结果（转录自论文表格）

- **效率**（表 1，约 300 笔预算）：像素 L2 / 感知损失全面优于四个基线（Stanford Cars L_pixel 56.92 vs 76.52–97.85；CUB 相对降幅 24.9–47.1%）。
- **用户研究**（表 2，MTurk 50 人、CelebA+CUB 共 100 对序列、10s GIF）：认为 Intelli-Paint 更像人画的占比 **69.09–86.50%**。
- **推理时间**（表 3，V100）：不带正则化 **0.948s**；带正则化 72.21s（慢约 76 倍）。正则化靠"高质量初始笔序"换收敛速度（对照 Optim 从头梯度优化 416.7s）。
- **论文自述限制**：只模仿过程的通用方面（不校准个人风格）；依赖显著性检测（漏检只退化为画进背景层，不伤成品）；需自监督训练，但推理时跨域泛化（文中所有结果图均出自仅用 CUB 训练的模型）。
- 副产品：渐进分层可作前景移除/修复的替代方案（非标准掩膜下比 GAN inpainting 自然）。

## 二、对我们的借鉴（分层：直接用 / 改造成我们的形态 / 后手）

### 直接用——Phase 1 设计条款

| # | 他们的机制 | 我们的翻译 | 依据/落点 |
|---|---|---|---|
| 1 | 渐进分层（背景层 → 前景按显著度） | 构图 prompt 增加"对象显著度排序，逐对象刻画；先背景后前景" | `agent-loop.md` 阶段制只有技法轴（铺色/湿画/干画/收尾），补一条语义轴 |
| 2 | 局部窗口随进度收缩（1→0.2） | 阶段批评只喂局部 crop：阶段 1–2 全景，阶段 3–4 目标区域特写 | lessons #3（批评粒度=执行粒度）拿到量化时间表 |
| 3 | 空间/颜色一致性惩罚 | 笔序规划守则：连续笔触不跳区、相邻笔触色彩渐变 | stroke 协议 v0.2 的规划提示词条款（我们用提示词而非 RL 奖励实现同一约束） |
| 4 | 两阶段"先冗余后裁剪" | 候选制（局部 3 选 1）+ 总笔数硬上限；砍冗余放最后一步 | lessons #4；keep-best 骨架已有，60-80% 削减量是预算参照 |
| 5 | 显著性漏检 → 退化为背景层，不伤成品 | 我们无目标图，用 VLM 从构图草稿取"视觉焦点排序"当显著性；漏检容忍 | 鲁棒性结论直接照抄 |

### 改造成我们的形态

- **评估维度**：训练奖励 = WGAN 判别器差分 + 焦点奖励（不是风格损失——感知/风格损失只出现在评估指标里，**此条纠正第一次粗读的口径**）。对应我们：VLM rubric 的 style 维（介质真实度）≈ 他们感知损失/判别器承担的"画味"角色；content 维 ≈ L2/焦点。lessons #2 的 aesthetics 维度从此有文献依据。
- **用户研究协议**：HIT 率 >90%、学历过滤、**重复种子一致性检查（同一对问两遍，不一致即弃）**——这条最值钱，直接迁移到 VLM 批评可靠性设计：关键阶段同一画面问两遍，不一致则降级为人工代评并如实标注。
- **速度教训**：正则化慢 76 倍 → Phase 1 不做"评分-重渲染"内循环；候选一次渲染、VLM 选 1（`agent-loop.md` 成本模型已定，这条是实证背书）。

### 后手（不进主线）

- **照片→水彩自动渲染**：若将来做 taste.md 四档的"传/同画"，两阶段结构照搬（LLM 出粗笔序 + 启发式裁剪），或为引擎做可微代理。引擎不可微 → 梯度正则化不可用 → 这正是他们保留 RL 的原因，也是我们保留 LLM+VLM 的原因。（更强路径见册二 Inverse Painting：成品画 → 过程可离线生成。）
- **画味判别器**：VLM 批评若成瓶颈，训练水彩判别器做分层奖励（他们的 WGAN 判别器先例）。远期。
- **同赛道阅读清单**：Xie 2013 Artist Agent（RL 水墨——与本项目血缘最近的祖先）、Paint Transformer、SPIRAL、CLIPDraw（文本→画，与我们输入形态最近）、Kotovenko 2021、StrokeNet。

## 三、诚实边界

1. 他们的 "human-like" = **笔序像人**；介质是 alpha 合成曲线，**没有水**。我们定义多"水自己干、自己渗"一条——介质腿无威胁，且他们的空白正是 Phase 0 已交付的五个工件。
2. 他们照片→画（有 ground truth：L2/感知损失可算、判别器可训）；我们一句话→画：**整套奖励公式不能搬**，只能翻译为 VLM rubric。
3. RL 成本不现实（500 万步训练、V100 级算力）；Phase 1 主线仍是 LLM 规划 + VLM 批评，这篇是设计背书与证据库。
4. 空象限复核：**过程可见 + 介质真实 + 自主创作** 三交集仍然为空——他们占"过程可见 + 自主"（且限于照片输入），介质真实缺席；sudoaquarelle 占"介质真实"，无 agent。我们的站位不变。

## 册二 · Inverse Painting: Reconstructing The Painting Process（SIGGRAPH Asia 2024）

> 结论先行：这是**临摹能力的路线图级论文**。它证明：给一张成品画，可以用从真实作画视频学到的模型，重构出"它可能是怎么画出来的"——产出带文本指令（"sky→mountain→grass→details"）和区域掩码的逐帧过程。对我们的意义分三层：① 教学/临摹内容生产（任意名画 → 可回放过程）；② 笔序计划的语义来源（其指令序列可直接喂给 Phase 1 的 LLM 规划器当"临摹题面"）；③ taste.md 里"已故大师的手只能从视频反推"这条后话，被它往前推进了一大步（**从成品图即可反推**）。但它的介质是像素级 diffusion，没有水、没有笔触协议——**过程可借鉴，渲染不可用**；模型是 GPU 级，进不了我们的 CPU/JS 引擎，角色定位为"离线计划生成器 / 研究参照"。

## 一、论文速览（已从 PDF 全文核实）

| 项 | 内容 |
|---|---|
| 题 | Inverse Painting: Reconstructing The Painting Process |
| 作者 | Bowei Chen、Yifan Wang、Brian Curless、Ira Kemelmacher-Shlizerman、Steven M. Seitz（华盛顿大学；UW Reality Lab + Google 支持） |
| 出处 | SIGGRAPH Asia 2024（东京），11 页，CC BY 4.0；DOI 10.1145/3680528.3687574 |
| 档案 | `research/papers/agent/3680528.3687574.pdf`；提取全文 `research/probes/invpaint_text.txt` |
| 任务 | 输入一张成品画 → 输出"它可能是怎么画出来的"逐帧时间线（白画布 → 成品，帧间固定时间间隔） |

### 与册一（Intelli-Paint）的同与异

- **同**：都解决"笔序像人"（由远及近、逐对象、分层）；都把过程当一等公民；都点名批评网格并行画法的机械感。
- **异**：Intelli-Paint 用 RL + 手写原则（分层/注意力窗口），输出 **stroke 参数**；本篇**从真实作画视频学**，输出**像素级关键帧 + 语义指令**，不输出 stroke。两者互补：一个给"笔触怎么排"的策略，一个给"画什么、画哪里"的语义顺序。

### 方法（两阶段）

1. **指令生成**：文本指令 = fine-tune LLaVA 1.5（横向拼接 [目标图, 当前画布] + 提问 → "sky"/"grass"/"details"）；区域掩码 = SD UNet 无噪声版（条件 = 文本指令 + 时间间隔编码，监督 = GT 差分掩码，BCE）。
2. **画布渲染**：扩散渲染器（SD 底座；ReferenceNet 注入目标图特征、浅 CNN 编码当前画布、NeRF 式位置编码注入帧间时间间隔 Δt、next CLIP 生成器补语义）。每步产出一张关键帧；测试时固定 Δt（默认 20s），白画布起自回归推进到收敛。

纯像素单阶段版会"一步画太多内容/山提前变黄"（论文 Fig. 5）——语义指令（text+mask）是必要修正，这一负结果本身就是我们"结构化协议"路线的旁证。

### 数据与结果

- **数据**：自采 294 条丙烯风景作画视频（Grounding DINO 分割出画布、剔手部/无变化帧），265 训/29 验，每幅约 27 帧，帧间平均 23.6s/22.0s，7261/783 个训练对。
- **五项指标全胜三个基线**（Timecraft / Paint Transformer / SVD）：LPIPS 0.364、IoU 0.418、DDC 32.66、DTS 1.273、FID 150.6（表 1）。
- **用户研究**：33 人评 1-5 分（逐用户归一化），胜过 SVD 1.9×、Paint Transformer 2.1×、Timecraft 3.0×。
- **指令质量**：91% 生成指令出现在 GT 指令集合（无序）；78% 进最长公共子序列（有序）；单步文本与 GT 对齐 72%（LLaVA 基座仅 31%）；掩码 IoU 0.70（Grounding DINO 分割仅 0.42）。
- **涌现性质**：帧间差分掩码按时间位置加权合成 "time map"，近似**逆深度图**——"由远及近"原则从数据里自己长出来，不是写进去的。
- **限制（自述）**：只训练于风景（人像翻车，Fig. 11）；风格受训练数据限制；大而罕见的物体（斗兽场）笔序错误。

## 三、诚实边界

1. 介质是**像素级 diffusion**：没有笔触协议、没有水、没有干燥时间线。作者原话：产出是 "plausible reconstruction"，不应视为真实作画过程的准确重建——**过程像人，介质不像水**。我们的引擎恰好补它没有的那半。
2. 训练数据是丙烯风景；泛化到水彩未经验证（水彩的湿接湿、回流开花顺序与丙烯不同）。若要做同类工作，前提是水彩作画视频数据集（素材存在，见 taste.md 诚实工程前提）。
3. GPU 级管线（SD 底座 + LLaVA + ReferenceNet），进不了我们的 CPU/JS 引擎。角色定位：**离线计划生成器 / 研究参照 / 未来服务化**，不是运行时依赖。
4. 它验证了"从真实作画视频学笔序"胜过"手写原则"（对 Timecraft/Paint Transformer 的对比）——长期启示：taste.md 学习阶梯 L2/L3 的"小模型拟合"路线，数据来源可以就是作画过程数据；册一的手写机制（分层/注意力惩罚）则告诉我们数据不足时该写什么。
